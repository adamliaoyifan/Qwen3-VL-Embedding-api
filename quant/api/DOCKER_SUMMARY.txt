互联网访问配置
================================================================================

✅ 服务已配置为绑定到 0.0.0.0 (所有网络接口)

要使其可通过互联网访问:

1. 获取服务器 IP
   curl ifconfig.me          # 公网 IP
   hostname -I               # 本地网络 IP

2. 配置防火墙
   sudo ufw allow 8000/tcp
   sudo ufw reload

3. 配置路由器端口转发 (如果在 NAT 后)
   - 外部端口: 8000
   - 内部 IP: 服务器本地 IP
   - 内部端口: 8000
   - 协议: TCP

4. 测试访问
   curl http://YOUR_PUBLIC_IP:8000/health

Docker 命令速查
================================================================================

构建镜像:
  docker build -t qwen3-vl-inference:latest -f api/Dockerfile .

运行容器:
  docker run -d --name qwen3-vl-service --gpus all -p 8000:8000 qwen3-vl-inference:latest

查看日志:
  docker logs -f qwen3-vl-service

停止服务:
  docker stop qwen3-vl-service

启动服务:
  docker start qwen3-vl-service

删除容器:
  docker rm -f qwen3-vl-service

进入容器:
  docker exec -it qwen3-vl-service bash

查看状态:
  docker ps | grep qwen3-vl

================================================================================
环境变量配置
================================================================================

QWEN_MODEL_PATH
  默认: Qwen/Qwen2-VL-7B-Instruct
  用途: 指定模型路径 (HuggingFace ID 或本地路径)

HF_ENDPOINT
  默认: (空)
  用途: HuggingFace 镜像地址 (如: https://hf-mirror.com)

CUDA_VISIBLE_DEVICES
  默认: 0
  用途: 指定使用的 GPU 设备

使用示例:
  export QWEN_MODEL_PATH="Qwen/Qwen2-VL-2B-Instruct"
  export HF_ENDPOINT="https://hf-mirror.com"
  ./deploy.sh

================================================================================
故障排除
================================================================================

问题: 容器无法启动
解决:
  1. 查看日志: docker logs qwen3-vl-service
  2. 检查 GPU: docker run --rm --gpus all nvidia/cuda:12.1.0-base-ubuntu22.04 nvidia-smi
  3. 检查端口: netstat -tuln | grep 8000

问题: 模型下载失败
解决:
  1. 使用镜像: export HF_ENDPOINT=https://hf-mirror.com
  2. 预下载模型到本地，然后挂载卷

问题: 无法从互联网访问
解决:
  1. 检查防火墙: sudo ufw status
  2. 检查端口转发
  3. 检查服务绑定: curl http://localhost:8000/health
  4. 检查服务器公网 IP

问题: CUDA 内存不足
解决:
  1. 使用更小的模型: Qwen2-VL-2B-Instruct
  2. 移除 --gpus all (使用 CPU，很慢)
  3. 减少批处理大小

详细故障排除: DOCKER_DEPLOYMENT.md
